# Meeting Notes

Repository-wide authorities: [data lifecycle](../workflows/shared-data-foundation.md), [storage and retention](../artifact-storage-policy.md), [applied MLOps](../workflows/applied-mlops.md), [research reporting](../../reports/README.md), and [continuous progress log](../research-progress.md). Meeting details remain here; log later milestones by linking the meeting rather than rewriting its minutes.

This directory stores concise group meeting and lecturer-guidance records for the COMP1884 project.

Meeting records are part of the project's accountability, coordination, and group-work evidence.

## File naming

Use one Markdown file per meeting:

```text
YYYY-MM-DD-short-topic.md
```

Examples:

```text
2026-09-20-project-commencement-meeting.md
2026-09-24-lecturer-guidance.md
2026-09-28-group-progress-meeting.md
```

## Required content

Each meeting note should contain:

- date;
- time;
- meeting type;
- purpose;
- attendees;
- topics discussed;
- decisions made;
- actions agreed;
- action owner;
- due date where applicable;
- status;
- blockers;
- related GitHub Issue / Pull Request / Decision Record where available;
- any lecturer/module-leader clarification actually required by the applicable module instructions, with evidence or unresolved status.

## Traceability

Where relevant, connect the meeting record to project evidence:

```text
Meeting discussion
    -> decision
    -> GitHub Issue / Decision Record
    -> implementation branch
    -> Pull Request
    -> merged result
```

The notes should record what was actually discussed at the meeting. Record lecturer teaching guidance separately from specific project feedback or approval; identify the person, date and scope. A later correction must be dated, preserve the original claim where needed for traceability and flag unresolved facts. Later project decisions should not be backdated into an earlier meeting record.
